# 六类编辑榜单与素材路线重组方案

状态：已实施（数据库迁移版本 46）

## 目标

让榜单分类直接对应编辑选题判断，避免“普通事件”成为兜底类，也避免开源技术、开源趋势、GitHub 项目重复分组。题材分类决定事件进入哪个编辑榜单；素材类型决定进入哪条生产路线，两者分别建模。

## 编辑榜单

| 榜单 | 收录边界 |
| --- | --- |
| 产品与技术动态 | 产品发布、技术变化与具体技术事件 |
| 大厂与商业战略 | 大厂业务布局、竞争、合作、收购与经营决策 |
| 职场与组织变化 | 岗位、薪酬、裁员、管理制度和工作方式变化 |
| 开源项目与开发者生态 | 开源项目、开发者社区和生态变化 |
| 行业趋势与市场变化 | 跨主体或跨时间的行业发展、市场结构与采用信号 |
| 政策与公共议题 | 监管、公共治理及对目标读者有明确影响的公共事件 |

明确与账号读者无关的事件不进入正式榜单或文章选题。没有足够信息确认题材的事件保持未归类状态，不能自动塞入“政策与公共议题”或其他兜底榜单。

## GitHub 项目路线

GitHub 单项目发现进入独立的“GitHub 项目发现”榜，使用 `material_type=repository`。它不占用六类编辑榜席位，也不自动创建文章候选。编辑可以提供选题理由和可核验依据，显式放行到文章路线；文章仍须通过通用事实门禁。项目图文路线独立保留。

涉及多个项目、行业采用或开发者生态变化的事件，按其编辑主题进入六类榜单；仅包含单个仓库资料的项目卡仍留在项目发现路线。

## 数据与实现规则

- `editorial_category` 保存六类选题归属；空值表示未归类，不是第七类。
- `material_type` 表示 `event`、`repository` 或 `custom` 等生产素材类型。
- `article_route_approved` 与 `article_route_evidence_json` 记录编辑对项目文章路线的明确放行和依据。
- 普通事件使用同一账号相关度热度分模型，在六个编辑榜内分别排序；项目发现榜独立展示。
- 迁移将旧技术/趋势类别转换为题材类别，将 GitHub 项目转入项目素材路线，并移除旧分类列和对应运行逻辑。无法可靠映射的历史题材留空。
- Social 生产只按素材类型进入事件、项目或自定义路线；技术解释、趋势判断是正文中的事实与论证要求，不再是独立分类或榜单。
